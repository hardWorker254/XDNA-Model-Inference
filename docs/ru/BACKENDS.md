# Бэкенды

В рантайме разделены **арифметические бэкенды** и **массивный/NPU-путь операций**:

- **CPU** (`backends/cpu`): host-kernels, эталонные численные реализации.
- **Vulkan** (`backends/vulkan`): вычисления на GPU (WGSL/`ash`). Доступен из CLI как `--backend vulkan` (все поддерживаемые ops) или `--vk-ops gemm,layn,gelu,softm` (выборочный offload). Неподдерживаемые ops/семейства/пути отклоняются по имени.
- **XDNA/NPU** (`backends/xdna`): диспетчеризация на массив и транспорты (например direct/xrt в зависимости от сборки). Используется через `--npu-ops` там, где реализовано для семейства.

`--npu-ops` (режим выполнения на массиве) и `--backend` (арифметика вне массивного пути) — независимые оси; комбинации принимаются только там, где поддержаны.

## Статус (кратко)

- CPU: эталонный путь для реализованных семейств.
- Vulkan: реальные вычисления на устройстве для поддерживаемых ops (gemm/gelu/layernorm/softmax/attn в шве; из CLI выбирается подмножество `gemm,layn,gelu,softm`). В планах/остатке: dispatch `conv/mproj/fft/logit`, оптимизации staging/batching и расширение покрытия семейств/серверов там, где это требуется.
- XDNA: массивные пути для выбранных проекций и свёрток семейств, где портировано (включая pose/hands/mppose в валидированных случаях). Отсутствие XRT/libxrt/libpython в direct-сборке (фичи/линковка) проверяется `tools/verify/verify_no_xrt.py`; при наличии платы и контейнера скрипт может дополнительно выполнить прогон.

## Сервер эмбеддингов

Сервер эмбеддингов поддерживает Vulkan ops (`--vk-ops` / `--backend vulkan`). Остальные серверные движки сейчас работают на хосте и отклоняют неподдерживаемые запросы бэкенда по имени.
