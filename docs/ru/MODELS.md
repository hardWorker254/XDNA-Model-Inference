# Модели и размещение весов

## Формат контейнера

- Основной: `.npum` (NPU Model). Legacy `.npue` принимается ридером; writer выдаёт `.npum`. Размещение/семантика сохраняются при смене магии, кроме явно задокументированных случаев.
- Контейнер содержит веса, конфиг/метаданные архитектуры и (для array-путей) предварительно тайленные панели/данные, связанные с дизайном, по необходимости.

## Источники и упаковка

- Веса transformer-семейств берутся из safetensors там, где это доступно (по текущему состоянию миграции); ONNX остаётся актуален для vision/graph-источников и fallback-сценариев.
- Упаковка выполняется Python-инструментами (`tools/pack/pack_npue.py`, `npue_tools/`).
- Пример (host-side f32 контейнер, сравнимый где угодно):

```sh
python tools/pack/pack_npue.py --model-dir models/<name> \
  --out models/<name>.npum --dtype f32 --no-embed-artifacts
```

## Поиск модели

По имени CLI/сервер ищет модель в:
1. `<root>/models/<name>.npue|.npum`
2. `<root>/weights/<family>/<name>/` (например `model.npue`, `<name>.npue` или контейнер внутри каталога)

По пути используется указанный файл контейнера как есть.

## Локальные артефакты и источник правды

- **Источник правды в git:** код, документация, конфиги, манифесты/скрипты (в т.ч. входы `tools/parity/fixtures/*`, если они поставляются), и небольшие метаданные, необходимые для воспроизведения workflows.
- **Сгенерированные/локальные кэши (не источник правды):** `target/`, `.venv/`, `.wheel-cache/`, крупные скачанные веса в `models/**`, кроме явно разрешённых политикой метаданных/конфигов/токенизаторных файлов.
- **Parity golden'ы:** `tools/parity/golden/` — контрактные артефакты; обновления должны быть ревьюенными и осознанными.

При добавлении/обновлении моделей фиксируйте требуемые файлы, шаги генерации и статус артефактов (обязательны для CI/dev smoke или только для полного локального/NPU-воспроизведения).
